# Модели предметной области и соответствующую функциональную декомпозицию

## Бизнесс-процессы

1. Создание задания
2. Установка критериев проверки — объединяющее понятие для тестов, метрик и других способов/критериев автоматической проверки.
3. Установка дедлайна
4. Изменение критериев проверки
5. Изменение дедлайна
6. Отмена задания
7. Отправка работы на проверку
8. Повторная отправка работы на проверку
9. Проверка работы согласно установленным критериям
10. Проверка работы на плагиат
11. Фиксация результата попытки
12. Ручная корректировка оценки преподавателем\*\*
13. Передача результата в LMS
14. Запрос оценок и истории их выставления с пояснениями аудирующими органами

**Критерии проверки** — абстракция, включающая тесты и метрики. Потенциальная точка расширения в будующем.
<br>

## Бизнесс-сущности

1. Задание
2. Критерий проверки
3. Решение
4. Попытка
5. Результат проверки
6. Оценка
7. Корректировка оценки

## Бизнес-правила

1. Студент может отправлять неограниченное количество попыток решения до наступления дедлайна.
2. После наступления дедлайна новые попытки решения не принимаются.
3. После наступления дедлайна критерии проверки задания не изменяются.
4. Преподаватель может вручную скорректировать выставленную оценку.
5. Решение не может получить положительный результат, если не выполнены обязательные критерии проверки.
6. Каждая отправка решения создаёт отдельную попытку и не заменяет историю предыдущих попыток.
7. Для каждой попытки фиксируются результат проверки и полученная оценка.
8. Результаты и история попыток должны сохраняться для последующего аудита.
9. Результат проверки должен быть передан в LMS.

### Особенности вариантов декомпозиции

**Вариант 1:**

- **работа с историей** результатов и подготовка данных для аудита объединены в компоненте `Аудит результатов`.

**Вариант 2:**

- **работа с историей** выделена в самостоятельный компонент `Управление историей`. Компонент `Аудит результатов` использует историю только для формирования данных для аудита.
- **ручная корректировка оценки выполняется средствами LMS.** Система автоматической проверки не предоставляет собственной функции корректировки оценки, но получает информацию о выполненных корректировках и сохраняет историю изменений. Механизм получения информации о корректировках требует уточнения.
